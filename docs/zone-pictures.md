# Zone pictures

All Zone details and saved artwork are visible before a first visit, including private interiors. Artwork grants no gameplay entry, attendance knowledge or character knowledge. Visiting remains an ordinary gameplay action.

Automatic pictures are enabled by default. The Village setting disables automatic requests; Freeze picture preserves one Zone's artwork. Manual Update, Replace, upload and Retry remain available with either control disabled. Update edits the latest picture to match the complete saved physical account. Replace generates fresh artwork using current scenery settings. Upload and Replace establish a new original reference without changing the freeze preference. Explicit removal prevents automatic recreation.

The existing System interpretation marks a meaningful, visible, enduring physical change when it accepts a Long-term details update. Completed construction/renovation and prepared interiors also nominate changed physical accounts. No extra model classifies artwork. Rewording, personality, art-style settings, incidental changes and Short-term details do not nominate automatic edits. Direct Long-term details corrections can be applied with Update.

Entry and settled Scene actions request pending artwork. All Zone kinds share the same missing-image creation path. Snapshot reads and browsing request no artwork; there is no redraw timer or once-per-Scene evaluation allowance. Work waiting behind another request coalesces by Zone and reads the latest physical account when it starts. A change that invalidates an in-flight result stays pending for a later action or visit.

One queue serializes Zone image requests across the Village. Automatic requests are limited to six per real hour and one per Zone per five real minutes. Durable reservations precede dispatch, count failures and invalidated work, and survive restart, Undo and Restore. DEBUG Village time does not advance these operational limits. A limit leaves work pending for a later visit/action or manual Update. Manual requests bypass automatic limits.

The latest accepted picture is the primary editing reference. The original remains a second architectural reference when every configured adapter supports multiple images. Complete previous and target physical accounts provide change instructions; overlong instructions block the edit with a visible status instead of silently truncating changes. Private notes, personality, nonvisual traces and Short-term details are excluded from editing instructions. Pictures create no gameplay facts.

The Villages capability classifier is conservative and based on Engine revision `46a0be6761a0757ffdaffbb55738e042d9ff26e4`. It recognizes supported GPT Image and Gemini image paths, AUTOMATIC1111/Draw Things, and ComfyUI/RunPod workflows with reference placeholders. Unknown connections or incompatible fallbacks retain the displayed picture and report why it cannot be updated. Detection makes no paid probes; reference support does not guarantee faithful editing.

A failed or interrupted request retains the displayed picture and requires a deliberate Retry. Retry uses current saved details and connections and repeats the failed operation (Update or Replace). Changed details alone do not authorize another automatic attempt after a failure. Unavailable connections and overlong instructions remain pending without consuming an allowance. A reset, Restore, replacement, removal, physical change or changed automatic controls invalidates stale results. Already dispatched provider work may still incur cost.

Only validated Engine-managed gallery files can be read as references. Original/current references and operational metadata remain server-side. Legacy saved pictures are adopted without automatic redraw; malformed baseline metadata is recoverable through Replace. Provider-free regressions cover lifecycle, persistence, privacy, limits and concurrency. Visual fidelity still requires a separately authorized real-provider trial. This feature changes Villages only.
