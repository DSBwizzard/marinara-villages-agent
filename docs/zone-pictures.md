# Zone pictures

Day/night imagery is standard. Existing description-writing requests infer whether a Zone has constant lighting; those spaces reuse one image. Unknown lighting defaults to a pair. There is no separate classification request or player-facing day/night control. Existing artwork is retained until normal eligible work updates it.

Pictures use stable daytime lighting, independent of generation time and passing weather, while respecting standing world rules and lasting physical conditions. Night derives from the canonical daytime image with the same architecture, viewpoint, furniture and possessions. Founding uses daytime artwork; play follows Village time and its IANA timezone. Map tint uses the same clock. Menu navigation does not reset its lighting transition. Closed Scenes retain their captured presentation.

Ordinary browsing shows the known Zone presentation, including physical prose and artwork. Founding seeds this account from the authored design and images without marking a Zone visited. Older unvisited Zones recover only explicitly persisted artwork context, never a baseline synthesized from current physical state. Without a historical design, public Zone identity and known Entrance architecture supply a neutral account for manual artwork. Settled entry/actions and eligible live Scene reconciliation replace this account from the player's current Scene context; held work retains its admitted account. Later unseen contents remain undisclosed. Known appearances never become physical, visit or access authority. Founding and REPAIR remain explicit authoring tools.

**Dynamic Images** governs automatic pictures. **Prevent dynamic image updates for this Zone** preserves its current artwork; switching saved appearances still works. The **Picture** menu offers **Generate new**, **Upload reference** and **Remove**, plus contextual Lore activity. Generate new and failed-work **Retry** use the known Zone account and remain available before visiting, after leaving and during renovations. They use its authored or remembered form, description, specification, lighting and artwork, plus current player-selected style/reference; live circumstances, occupants, adjoining Zones and newly matched Lore are excluded. Saving a reference is model-free and permitted while absent. It leaves the existing backdrop in place and changes no game facts. The next eligible generation reconciles the known description with the upload's compatible artistic style; unrelated reference subjects are excluded. Night derives from that generated daytime result, never directly from the upload. Remove clears artwork and its reference and prevents automatic recreation, without importing unseen lighting or recording a visit.

Accepted lasting physical changes, completed renovations and prepared interiors mark artwork pending. Entry and settled actions request it only while the player is actually present. Snapshot reads and browsing never request images; there is no redraw timer. Short-term details, rewording, personality and style settings do not trigger edits. Automatic queued work coalesces by Zone and rechecks presence immediately before provider dispatch, including the night companion. Manual work instead rechecks its complete observation and reference. An admitted result may finish after departure only if its physical/observation context and revisions still match.

Artwork generation, reference upload and removal address the selected Place and exact Zone ID. Missing or invalid Zone IDs are refused before model work or saved changes.

One queue serializes image requests. Automatic work is limited to six images per real hour and one update per Zone per five real minutes. The day/night stages of one update may run together; each consumes its own allowance. Durable reservations count failures and invalidated work and survive restart, Undo and Restore. DEBUG Village time does not advance operational limits. Pending work waits for a later visit/action when capacity is unavailable. Explicit Generate new and Retry bypass automatic limits and freeze controls, while retaining observation, pause and stale-result fences.

Automatic physical edits use the latest accepted image, plus the original architectural anchor when all configured adapters support multiple references. Manual retries use only remembered artwork. Complete previous and target physical accounts are retained; overlong instructions block generation instead of truncating changes. Private notes, personality and Short-term details are excluded. Reference support is conservatively detected without paid probes. Unsupported connections retain artwork and report the problem. A failed/interrupted request requires deliberate Retry; Retry resumes the failed stage and preserves completed daytime artwork. Changing a reference, removal, reset, Restore or conflicting physical changes fence late results. Already dispatched work can still incur cost.

Only validated Engine-managed gallery files can be read as references. Provider-free tests cover lifecycle, persistence, projection privacy, presence, limits and concurrency. Reference fidelity requires a separately authorized real-provider trial; prompts cannot guarantee exact visual compliance. This feature changes Villages only.
