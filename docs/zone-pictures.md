# Zone pictures

Automatic Zone pictures are enabled by default. The village setting disables all automatic picture calls; Freeze picture preserves one Zone's current artwork. Manual upload and generation remain separate actions. Upload artwork or Regenerate artwork replaces that Zone's base and current picture without changing its freeze preference.

Each Scene persists one evaluation per successfully entered Zone, including Exterior. A return to the same Zone makes no additional automatic request. Changes while staying there wait for its first entry in a later Scene. An evaluation is consumed even when no rendering is needed, the feature is disabled, or its connection is unsupported. Re-enabling does not generate immediately.

The latest accepted picture is the primary editing reference. The original is retained as a second architectural reference where the primary and fallback adapters support multiple images. Saved physical contents and bounded resident context provide continuity and complete change instructions; pictures do not create gameplay facts. Private notes and nonvisual traces are excluded. No separate vision or furnishing simulation is introduced.

The Villages classifier is conservative and based on Engine revision `46a0be6761a0757ffdaffbb55738e042d9ff26e4`. It recognizes supported GPT Image and Gemini image paths, AUTOMATIC1111/Draw Things, and ComfyUI/RunPod workflows with reference placeholders. Unknown connections or incompatible fallbacks retain the displayed picture without an editing call. A workflow accepting a reference does not guarantee faithful editing. Detection makes no paid probes.

Failure preserves the existing picture and suppresses identical automatic retries. Retry artwork is available after a failed edit; it uses the current connection and access rules. Changed inputs may be attempted on a subsequent Scene's first entry. Overlong change instructions are retained without generation rather than silently truncating physical changes. Replacement, reset, freezing, disable/re-enable, and physical changes invalidate pending results. Provider requests already dispatched may finish and incur cost; their invalidated results are discarded.

Only validated Engine-managed gallery files can be read as references. Original/current references remain in saved Zone metadata, which is excluded from client snapshots. Existing saved pictures are adopted without generation; unchanged physical state is not re-rendered solely because of migration. Explicit picture removal is not undone by personalization.

Provider-free regressions verify dispatch, persistence, privacy, concurrency and controls. They do not verify visual fidelity. A separately authorized real-provider trial is needed to assess successive room edits. Shared Engine capability discovery and an editing-required fallback contract would reduce future compatibility maintenance, but this feature changes Villages only.
