# Zone pictures

Day/night imagery is standard. Existing description-writing requests infer whether a Zone has constant lighting; those spaces reuse one image. Unknown lighting defaults to a pair. There is no separate classification request or player-facing day/night control. Existing artwork is retained until normal eligible work updates it.

Pictures use stable daytime lighting, independent of generation time and passing weather, while respecting standing world rules and lasting physical conditions. Night derives from the canonical daytime image with the same architecture, viewpoint, furniture and possessions. Founding uses daytime artwork; play follows Village time and its IANA timezone. Map tint uses the same clock. Menu navigation does not reset its lighting transition. Closed Scenes retain their captured presentation.

Ordinary browsing shows the known Zone presentation, including physical prose and artwork. Founding seeds this account from the authored design and images without marking a Zone visited. Settled entry and eligible Scene reconciliation record the ordered observable Room entries, including any temporary entries still current. Held work retains its admitted account. Offscreen Zones keep their last known appearance. Manual generation requires an authored or observed account. Founding and REPAIR remain explicit authoring tools.

**Dynamic Images** governs automatic pictures. **Prevent dynamic image updates for this Zone** preserves its current artwork; switching saved appearances still works. The **Picture** menu offers **Generate new**, **Upload reference** and **Remove**, plus contextual Lore activity. Generate new and failed-work **Retry** use the known Zone account and remain available before visiting, after leaving and during renovations. They use its authored or remembered form, description, specification, lighting and artwork, plus current player-selected style/reference; live circumstances, occupants, adjoining Zones and newly matched Lore are excluded. Saving a reference is model-free and permitted while absent. It leaves the existing backdrop in place and changes no game facts. The next eligible generation reconciles the known description with the upload's compatible artistic style; unrelated reference subjects are excluded. Night derives from that generated daytime result, never directly from the upload. Remove clears artwork and its reference and prevents automatic recreation, without importing unseen lighting or recording a visit.

When the observed appearance differs from the saved image's account, the interface can mark the image out of date. Room text changes, expiry, correction and Project preservation queue zero image requests. Entry can request eligible automatic artwork, such as a first image or a pending reference, while the player is present. Snapshot reads and browsing do not dispatch image work. The queue coalesces by Zone and rechecks presence before automatic dispatch, including the night companion. Manual work rechecks the complete observation and reference. A result can publish after departure only if its captured context and revisions still match.

Artwork generation, reference upload and removal address the selected Place and exact Zone ID. Missing or invalid Zone IDs are refused before model work or saved changes.

One queue serializes image requests. Automatic work is limited to six images per real hour and one update per Zone per five real minutes. The day/night stages of one update may run together, and each consumes its own allowance. Durable reservations count failures and invalidated work and survive restart, Undo and Restore. DEBUG Village time does not advance operational limits. Pending work waits for a later eligible entry when capacity is unavailable. Explicit Generate new and Retry bypass automatic limits and freeze controls while retaining observation, pause and stale-result checks.

Eligible image edits use the latest image and can also use the original architectural anchor when the connection supports multiple references. Manual retries use remembered artwork. Overlong instructions block generation so the complete previous and target accounts survive. Concealed entries and private knowledge stay out of the artwork prompt. Reference support is checked without paid probes. Unsupported connections retain artwork and report the problem. A failed or interrupted request requires deliberate Retry, which resumes the failed stage and preserves completed daytime artwork. Changing a reference, removing artwork, resetting, restoring or changing the captured appearance can invalidate a late result. Already dispatched work can still incur cost.

Only validated Engine-managed gallery files can be read as references. Provider-free tests cover lifecycle, persistence, projection privacy, presence, limits and concurrency. Reference fidelity requires a separately authorized real-provider trial; prompts cannot guarantee exact visual compliance. This feature changes Villages only.
