# Villages architecture and compatibility

Feature ownership, host access and saved-state projection are separate. The narration-first cutover requires fresh storage and preserves all bytes of older saves.

## Code ownership

Maintained source is in `packages/villages/src`.

| Owner           | Responsibility                                                                |
| --------------- | ----------------------------------------------------------------------------- |
| Client features | Screens, feature state and commands                                           |
| Client shell    | Navigation, shared snapshots, responsive state, presence and feature assembly |
| Server entry    | Assembly and lifecycle of activation-owned services, adapters and jobs        |
| Server features | Request coordination through explicit contracts                               |
| Domain          | Saved models, decoding, calculations and rules without host I/O               |
| Adapters        | Engine public APIs, storage, generation, accounting and diagnostics           |
| Jobs            | Owned background work and finite preparation                                  |

`scripts/feature-interfaces.mjs` declares cross-feature contracts. Architecture checks enforce private feature boundaries, client/server privacy, dependency direction and absence of cycles. Shared support does not import shell assembly or private feature implementations. Public contracts expose consumed values and commands rather than another feature's private state or hook types.

New layers and interfaces need a concrete purpose. Tests import the actual owner rather than relying on forwarding exports.

## Activation and request lifetimes

Each activation owns its services, caches, queues, operation maps and host connections. Asynchronous work retains its originating owner. A missing or disposed activation cannot borrow another world's services, even when identifiers match. Cleanup from an older owner cannot stop or clear its replacement.

Client commands claim admission before mutation and preserve the originating world, selection and request identity. Results, errors and cleanup belong to that claim. Reset, disposal or replacement retires old work; functional acknowledgments preserve newer edits. These lifetimes do not impose global ordering on independent full-snapshot responses.

Cancellation revokes authority to apply late effects. It does not promise that an upstream provider physically stopped or that an uncertain request was unbilled. Existing operation deadlines, request reservations and recovery records remain authoritative.

See [activation dispatch ownership](activation-dispatch-ownership.md) and [activation cleanup](activation-cleanup.md).

## Scenes and privacy

Places and Venues contain Zones. A Scene continues across movement between Zones. Admission captures time, attendance, positions, activities, connections and current circumstances. Background changes leave an admitted request intact. The saved request records the fitted continuity and Episode sources and the native authority the GM received. Accepted effects extend the Scene through its Episode acknowledgement. Closed Scenes stay closed.

Source spans, witnesses, authority, revisions and physical receipts bind proposed effects to the saved interaction. Hearing, understanding, disclosure, entry and permission to change a space remain separate. Domain validation determines actual effects after model interpretation.

Ordinary snapshots expose bounded playback, exact original submission rows and player-visible authority. Original submission rows have an empty resident audience. Private diagnostics, raw provider output, fitted readsets and undiscovered interiors stay server-side.

See [Scene privacy](scene-response-privacy.md), [System responsibilities](system-ownership.md) and [generation lifecycle](generation-pipeline.md) for the detailed contracts.

## Saved work and compatibility

The current runtime uses Village format 18, physical Scene storage format 15, logical Scene format 5 and captured Scene context version 4. The common history payload uses format 3 with a format-1 manifest for continuity, accepted Episodes, Places and mail. Common continuity and Episode collections each use format 1. The Village CAS publishes the compact history reference with matching mechanics. Scene acknowledgement is a separate resumable stage. See [Memories](memories-core.md).

Background jobs use response-storage format 4 and response-body format 2: a physical request claim precedes dispatch, and one immutable, opaque response body is published before its compact job reference. Normal and late replies share that path. Before Retry, replacement or obsolescence releases unfinished evidence, the existing background-history kind retains an exact, content-addressed native before-image under the same repair admission as the current-job CAS. Competing writes cannot overwrite a richer before-image, and a lost publication acknowledgement verifies the existing immutable bytes. Only positive proof from the live invocation can release a reservation that never entered its provider. Responses retain their original principal request identity before supersession checks; uncertain outcomes remain held. Successful effects release settled recovery payloads only with their exact durable World receipt; physical request uncertainty remains owned independently. Before a physical World write overwrites or deletes a positive background receipt, the existing storage boundary preserves a narrow immutable background-completion proof, including repair journal replay. Simulated intermediate receipts cannot manufacture proof. Cleanup can retire fully known acknowledged historical before-images; pending physical claims, unreconciled late responses, request uncertainty and accepted replacements remain held. Current work, saved World and departure captures, available Undo and prepared repairs retain their matching proofs. Historical roots retire before bodies, and the last unowned proof retires last. Historical response selection, rejection accounting and Retry/Dismiss controls remain separate.

Background inputs retain their admitted identity and exact request sources. Before a source job can publish Village effects, the repository rereads its physical slot under repair admission. It checks the world seed, job ID, instance, attempt, owner, queued or running status and absence of a replacement. Publication validates or rematerializes unprotected dependencies before the owner CAS. Current work, checkpoints, available Undo and prepared repairs protect their exact dependencies. Comparison fingerprints own no data.

Both background replies and Scene operation-evidence format 3 retain a payload checksum, so a prospective publication claim can validate bytes before its completed owner reference exists. Recovery preserves deliberate retry holds and reuses saved replies; metadata-only usage previews load bodies only for an eligible recovery parser. Current jobs, retained attempts, prepared repairs and available Undo records validate their response dependencies. Scene response selectors retire only after normal Scene retirement has published its format-2 terminal with matching accepted Episode identities, every dispatch has settled, and no current, checkpoint, Undo or prepared-repair source owns that Scene. A gathering's fixed prospective Scene ID also owns responses before its native Scene exists. Any retained Scene version conservatively keeps its selectors and purchased bodies; no age or count limit applies. Idle cleanup validates all owners and physical terminal/Scene identities before removing selectors, then sweeps unreferenced bodies. Interrupted deletion leaves bodies available, and late callbacks require their exact saved claim under full repair admission before publication, so they cannot recreate retired allocations. The existing terminal supplies replay protection; no second tombstone lifecycle is introduced. Background bodies enter the same validated sweep only after every current, historical, available Undo and proposed-repair owner has been traced. Background publication checks its exact durable physical claim under full repair admission; ordinary replies read only their current slot, while late replies may scan retained attempts. Retiring the last owner therefore prevents an old callback from recreating a collected body. Current compact receipts and unfinished historical ownership remain independent of body cleanup.

The common history manifest owns separate typed trees for continuity records and versions, accepted Episodes, Places and correspondence. Each holder has its own current revision. Old versions and Episodes keep the evidence needed for continuity and recovery. Warm publication shares immutable unchanged leaves and writes only changed payload blocks and their directory paths. Cached values grant no ownership. Readers opt into history and stay admitted until their referenced pages load. Ordinary authority saves preserve the compact head.

Saved generation, validation, committed effects and Scene bookkeeping are distinct stages. Claims precede provider dispatch; completed responses and effect receipts support local replay. Compare-and-swap retries reuse saved output and preserve request accounting.

Jobs and operations bind the village seed, subject, source revision, attempt and admitted contract. Each fresh background job also persists a unique instance UUID before dispatch. Ordinary Retry keeps that UUID and advances its attempt; recreating or replacing a job allocates another UUID. Response claims retain their original instance and attempt, including when a new instance borrows a completed purchased response. A foreign pending claim is invalid. Delayed saves, source-job World publications and public Retry actions check the exact instance; a reused logical job ID or counter grants no authority. Current-job CAS and World publication share the existing authority lock through acknowledgement, with clock observation and immutable preparation outside that lock. Reset, removed residents, changed inputs, supersession and teardown fence late effects. Existing operations retain their original prompts and stage contracts rather than silently adopting new generation behavior.

Reads, polling, notices, diagnostics and storage retries do not authorize paid dispatch. Unknown provider outcomes require deliberate retry. A successful model response does not by itself establish a committed effect.

Engine document writes are buffered, without a package-visible durable flush barrier. A hard crash can lose recently acknowledged claims or responses. Recovery records improve normal-operation replay; they do not provide crash-proof billing deduplication.

Common continuity supplies the ordered current room account. Scene changes replace or retire only the affected fitted entries and preserve unrelated entries. Witnessed nonstructural decoration, rearrangement, repair and plausible damage use common keeps. Structural changes and official Venue functions use native Projects. Native world, artwork, preparation and repair operations retain their scoped authority, revisions and receipts. See [Places](places.md) and [Memories](memories-core.md).

Saved-data changes require an explicit format decision and preservation of existing storage.

The current build requires a fresh format-18 Village. Unsupported formats are rejected before recovery or provider dispatch and their bytes remain untouched. Older saves stay in their independent storage with their matching runtime. Billing evidence, unknown outcomes, explicit pauses and recovery holds retain their protections.

### Recovery disposition

Scheduling labels and failure messages do not establish that evidence is disposable. The domain recovery classification checks saved work and uncertainty before accepting a terminal label:

| Disposition      | Required evidence and behavior                                                                                                                                          |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Pending          | Accepted work is queued, running or paused. Retain its admission and continuation; an explicit pause does not authorize dispatch.                                       |
| Recoverable      | A saved reply, result or partially committed effect permits useful continuation. Reuse purchased output before considering a replacement request.                       |
| Uncertain        | A dispatched request, effect or publication has no conclusive outcome. Retain its reconciliation evidence and replay guards; do not automatically purchase a duplicate. |
| Completed        | Required effects and publication are acknowledged and no continuation remains. An inconsistent completed label cannot override retained unfinished evidence.            |
| Failed           | The attempt ended conclusively without saved work or an unresolved obligation. Ordinary diagnostics can eventually be retired independently of replay protection.       |
| Safely abandoned | Dispatch/callback authority is fenced and committed effects reconciled. An obsolete label alone does not prove this disposition.                                        |

Before abandonment, Scene recovery reconciles any already committed Episode. Abandoning an uncommitted request preserves its exact input, responses and accounting evidence and releases its inactive Scene snapshot. Close recovery uses the current Scene. Earlier checkpoints and Undo records own their original snapshots independently.

Compaction requires a terminal disposition, preserved accounting/replay protection and an owner for every still-needed piece of evidence. Full receipt deletion additionally requires a durable closed scope, epoch or high-water rule that rejects every possible replay, and no remaining reference. Age, a failure label and diagnostic retention limits are insufficient. These requirements precede the later compaction implementation; the current background cleanup only adds a guard against discarding pending, recoverable or uncertain records. It does not enable new pruning or paid retries.

An explicit Village Reset ends the old world's ownership and retains the established removal of its private jobs after active work settles. The new seed fences their application to the replacement world. Removing a resident or marking a current-world job obsolete does not confer that authority. Malformed records whose ownership cannot be established remain protected. Unknown token counts are accounting uncertainty, not proof that a completed request is still unfinished.

Unapplied REPAIR reviews are administrative previews produced by simulation. They have no committed effects and are never the sole owner of a paid response: their authoritative source records remain unchanged. Keep at most ten valid current-world previews, discard them on explicit cancellation, and retire an applied preview in the same journal as its effects and acknowledgment. Apply checks the retained preview and its unique creation token before publishing any effects. A repeated request may recreate an evicted/cancelled review, but its new token cannot restore an old Apply's authority or let a late Cancel erase the replacement. Drafts remain client-owned. Unfinished repair journals recover before cache retirement; unknown/corrupt or foreign ownership is retained. This cache limit does not prune player history, Undo or checkpoints.

### Reference lifetime

Ownership is explicit and world-scoped. Do not infer references by scanning arbitrary player/model prose. Current storage uses existing payload intents, operation records and captured facts; later storage changes must preserve these owner obligations before adding deletion:

| Owner                                             | Protected dependencies and release boundary                                                                                                                                                                                                                  |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Current authority and meaningful retained history | Current facts, exact evidence, individual knowers, corrections, resolutions and Forget suppression. No automatic history expiration or lifetime cap.                                                                                                         |
| Active/frozen Scene                               | Captured attendance, privacy, facts, accepted own effects, evidence and media. Release only after established retirement and transfer of retained evidence ownership.                                                                                        |
| Departure capture and unfinished catch-up         | Exact historical facts, admissions and unsettled outcomes. Release after settlement or proven safe abandonment; retained outcomes remain owned by history.                                                                                                   |
| Unfinished or uncertain operation                 | Admission, saved paid replies, commit/publication evidence and assets. Release only after reconciliation and terminal disposition.                                                                                                                           |
| Available repair Undo                             | Exact inverse dependencies and assets. Retain the ten most recently committed successful repair payloads; consumed Undo does not resurrect older payloads. Permanent repair headers preserve changes, audiences and Undo provenance after availability ends. |
| Automatic/manual checkpoint                       | The complete transitive snapshot and media dependencies. Retain ten automatic checkpoints by committed publication order; manual checkpoints remain until explicitly deleted. Recovery/explicit holds override ordinary eviction.                            |
| Saved evidence and replay protection              | Exact cited sources and information that rejects duplicate effects. Release only after ownership transfer or a proven replay fence with no remaining reference.                                                                                              |

Publication protects existing and proposed dependencies before creating bodies, validates them, then publishes through the existing CAS/repair fence. Ambiguous or interrupted publication retains its intent. Cleanup may release superseded data only after new ownership commits, and must recheck owner revisions and outstanding intents under the same fence before deletion. A writer cannot attach a new reference concurrently with that deletion. Missing, corrupt or unknown ownership defers cleanup. Restore validates/protects its dependencies before publication and cannot rewind operation epochs or replay protection. Startup reconciles unfinished publication/repair journals before cleanup.

Checkpoint format 2 headers and separate Undo bodies reference content-addressed native document snapshots. Snapshot data remains identical to its source so Engine can see the same Gallery owners. Snapshot identity includes the complete source, including its saved clock. Configuration saves preserve the original setup identity. Plans and format-3 repair journals reference immutable after-images and before digests, with opaque packets only for validated create-only history pages. Application composes effects, retention ownership and plan retirement in one overlay and journal. Every replay frame and source is validated before the first effect. Preparation and owner publication remain admitted through the existing repair gate; cleanup cannot enter that gap. Deleting a manual checkpoint releases its references with one CAS and retains a minimal token tombstone so a delayed save cannot recreate it. Physical cleanup validates all retained owners, including other world scopes, before its first deletion. Each retained review has its own proposed-write overlay; virtual pages cannot validate a missing physical checkpoint dependency. The history tracer follows references inside serialized Scene headers and visits shared structural pages once per lookup scope. Malformed or missing ownership defers deletion. After all writers drain, well-formed abandoned intents can release partially created unowned artifacts.

Keep native media reference fields visible to Engine's Gallery protection even when historical prose is stored opaquely. Cleanup acts only on attributable Villages candidates. Avoid authoritative reference counts or a generalized collector: extend existing intents/fences and explicit owner manifests only where a concrete storage change requires them.

Storage admission is shared by canonical Engine backend identity across replacement module snapshots. Disposed activations retain their outstanding admission until invoked host writes settle; they cannot publish new work. Startup journal readiness is invalidated when the shared recovery epoch advances. Full history reads remain admitted across their entire load. Cleanup acquires the same exclusion before tracing and deletion; newly arriving gameplay waits for cleanup rather than receiving a repair conflict. Package installation still uses the guarded stopped-runtime boundary for the first deployment of this participation contract.

An exclusive repair operation validates existing history pages through one private, operation-local inventory, including its per-ID commit guards and journal recovery preflight. This avoids repeated Engine table scans without a persistent index or an extra global membership guard. Expected absence still requires an individual lookup to detect wrong-kind ID collisions. Staged writes override the physical inventory; physical page writes invalidate even an in-flight inventory after a lost acknowledgement. Returned records are detached, and the inventory ends with exclusion. Ordinary gameplay retains selective page reads. Administrative operations trade a full retained-page read and temporary memory for fewer table scans; new-page creation and other Engine storage costs remain separate.

One initial idle sweep recovers allocations from an earlier activation. Later sweeps are coalesced after approximately the greater of 1 MiB or the prior live footprint has been allocated. This footprint includes retained owner metadata and owned sprite bytes as well as immutable bodies, so many manual checkpoints do not cause increasingly frequent full owner scans. Estimates are activation-local and may safely overcount failed creates; no routine persistent counter writes or new scheduler are needed. Ordinary saves below that allocation budget do not scan retained history. Cleanup does not expire meaningful Memories, correspondence, Wishes, relationship or repair history, or remove manual checkpoint headers.

Each Sprite Manager upload claims a fresh, never-reused Villages UUID path before writing, with its exact filename, digest and byte count; a separate acknowledgement precedes owner publication. Existing repair admission spans upload through the final World or setup-draft save. World, departure, both social outboxes, frozen/admitted Scenes, background current/replacement/history and setup drafts retain their typed artwork references; checkpoints, available Undo and proposed repairs retain their transitive sources. Removing artwork releases only the current assignment. The existing collector validates every retained owner before deleting an unowned attributable file, and retains its allocation until Engine acknowledges deletion. Image-serving 404 also covers corrupt files and is not deletion proof. Directory inventories are indexed once per asset per sweep. Uncertain uploads remain held for their entire Engine process, across package replacement; only a full process restart proves that producer has exited. Gallery images, Engine character originals and files without allocation records are outside automatic deletion. The managed UUID directories are private allocation namespaces, not general-purpose user libraries.

Media cleanup that encounters an unavailable Engine remains eligible for the next admitted idle event. Integrity failures retain allocation backoff; neither path starts a retry timer.

See [response recovery](scene-response-recovery.md), [Scene continuity recovery](scene-continuity-recovery.md) and the [generation lifecycle](generation-pipeline.md).

Native Scene ownership binds row IDs, Scene IDs, Village seeds and captured scopes before admission or publication. Metadata reads leave private context unloaded. Checkpoints validate all transitive Scene pages before publication or restoration. Cleanup traces current and checkpoint, Undo and repair versions using their own proposed-write overlays. Missing ownership holds deletion. Native Venue and media fields remain visible to Engine.

Scene storage format 15 publishes separate typed, counted transcript and submission trees in the current Scene and its admitted snapshot. The collections share bounded immutable pages, caches and tracing with distinct namespaces. Each submission occupies one block. Changing its recovery state rewrites that turn without reserializing neighbouring request contexts. Returned arrays cannot mutate cached history. Position and staging identities bind to the captured participant directory. Hearing comes from each exact line's audience and sound-only projection. Input rows carry an empty resident audience. A separate History index keeps eligible line identities, positions and public-output digests. Metadata reads refuse unloaded history or continuity. Recovery loads the needed submission mechanics explicitly.

Scene operation responses and completed checkpoint values have separate immutable bodies. Each reference binds the Scene, Village seed, logical operation, frozen input/revision and checkpoint or attempt key. The current operation owns its admitted Scene snapshot; that snapshot cannot contain another operation. Logical operation contexts hydrate exact values without changing synchronous checkpoint access. These stage values contain text, domain IDs and evidence, not independently allocated media: the typed World and Scene records own actual media. A fixed prefix makes each serialized JSON envelope opaque to Engine reference traversal, including fitted requests and prose resembling asset IDs. An envelope distinguishes an undefined result from null and an absent result reference. Publication checks the exact payload digest and immutable document identity. This bounds ordinary native operation writes and warm serialization. Publishing a new stage still writes its actual fitted evidence and response.

Physical dispatch claims precede model work. Normal and late replies use the same signature-keyed Scene receipt and an atomically published body before Scene adoption. Rejection fences the exact selected physical response, independently of the logical retry that adopted it; older callbacks cannot select a replacement after that fence. Local checkpoint claims similarly precede stage work and protect a prospective body across failed acknowledgements. Recovery adopts an already saved parsed value rather than recomputing it. Writing-completion checkpoints only return the independently retained raw response and share that body. Cleanup follows current operations, explicitly retained abandoned operations, checkpoint/Undo/review versions, selected receipts and unfinished publication claims. Missing or malformed ownership holds every deletion. Scene retirement does not delete response receipts: a checkpoint made before the response arrived can still restore its earlier request. Receipt retirement requires its separate closed-scope proof.

Full work admission covers page allocation through the Scene CAS. A drained cleanup therefore sees either a complete native owner or abandoned, unowned pages; this path needs no separate publication-intent record. Cache entries alone cannot establish ownership or publish missing dependencies. Checkpoint and cleanup passes validate each shared block once, including canonical line shape, counts, duplicate IDs and cast dependencies, under separate proposed-write overlays. Retirement validates the authored source before logical coercion. Submissions and model context construction remain separate costs; transcript sharing alone does not bound a complete Scene request or all Scene persistence.

Departure captures store detached native facts and the captured continuity and Episode revisions in the exact Village scope. Calendar, resident, narrative and Project projections use the captured facts. Reconciliation checks the retained revision fences. Restoration discards the active absence capture, while retained checkpoints keep their saved capture and its history dependencies.

Resident catch-up inputs and capture fences use comparison fingerprints in the full world namespace. Fingerprints own no data. Missing context cannot authorize resident work. Social encounters and meeting history have no automatic lifetime limit.

Mailbox responses contain at most 50 letter summaries and an independently pageable set of at most 50 recovery entries. Their row budgets are 64 KiB and 16 KiB respectively. Exact bodies are fetched individually; unread incoming previews and unseen purchased outbox replies are not exposed. Deterministic position cursors are scoped to the Village and folder without owning or pinning history. Current requests index jobs, pending errors and message identities once rather than scanning the complete mailbox for every row. This bounds response/rendering/serialization work; it does not make cold history hydration, metadata scans or existing outbox settlement an indexed backend query.

The public snapshot and correspondence responses carry an opaque seed/setup scope. Letter summaries/details additionally carry a computed fingerprint of content, source identity and accepted disclosures, excluding read/status/error fields. Detail, Read and Retry require the selected fingerprint: checkpoint restoration can rewind the request-ID directory while retaining the same Village scope. Read still publishes the complete permitted disclosure evidence before acknowledging readAt, without model work. Commands and shared outbox settlement take existing work admission and authority ownership before consulting shared tasks. The client keeps one selected body independently from index pages, rejects stale query/detail/command responses, retains scope-bound drafts/request identities and follows existing snapshot updates without a dedicated settled Mailbox timer.

The Scene History drawer uses a separate read-only endpoint with at most 40 public entries and a 128 KiB response budget, preserving one oversized exact entry whole. Older/Newer replace the displayed page. The endpoint seeks the public index and selected transcript blocks without hydrating frozen context, submissions or the complete transcript. Cursors bind Village scope, Scene and a digest of ordered public output; hidden-only changes leave them valid, while changed or restored public output requires refresh. Neither private offsets nor private source heads enter responses. The current and admitted Scene owners publish the index atomically with their source heads under existing work admission. Checkpoints, Undo and repair overlays trace the same index; missing ownership blocks cleanup. Coordinator timing saves rebind the index source within the same CAS; changes to effective hearing rebuild it before publication, while admitted snapshots keep their independent captured index. Ordinary operation checkpoints do not reread transcript prose. Range reads stay admitted until their response is constructed. Active and command Scene responses also carry a bounded playback window of complete main/aside moments. Each moment references its existing prose and immutable first/last paragraph presentation (visible poses and desktop/phone placement), without copying the encountered cast into every frame. A single current staging accumulator continues publication; initial staging identities are captured once. Moment counts and paragraph prefixes support exact global reading counters. Playback cursors bind the exact public anchor and remain valid across appends; changed or restored anchors require an explicit refresh. A separate cancellable client lane cannot replace current Scene authority. Scoped line/paragraph bookmarks preserve older reading positions; a reply larger than a window backfills its first unread passage. One recently closed playback owner in the existing active-venue pointer keeps the final Scene readable across navigation/restart, until a new native Scene and its pointer commit or Reset removes it. Missing or foreign closed ownership holds cleanup and restoration. Close acknowledgements include the latest exchange; the existing changes feed drains any older recovered notices in bounded pages. These bounds concern history-dependent response and rendering work; full private Scene hydration, context preparation and the encountered participant header still have separately measured costs.

## Engine and validation

Villages uses declared permissions and public Engine APIs. Private Engine implementations are not bundled.

Locked dependencies and pinned public declarations support builds without an Engine checkout. The repository builder owns generated payloads and deterministic archives; maintained source, tests and documentation are committed.

[DEVELOPMENT.md](../DEVELOPMENT.md) owns commands and release steps; [AGENTS.md](../AGENTS.md) owns development principles. Provider-free tests establish their exercised contracts, not live-provider quality or actual Engine integration.

The former extraction ledger is retained in Git history. This document describes the resulting boundaries rather than intermediate task status.
