# Model JSON recovery

App-generated structured responses request JSON mode. Villages uses the pinned bundled jsonrepair library behind a domain-owned, value-preserving policy, followed by the current application parser. Saved settings, persisted records, image-service protocol data and authored content do not acquire model-text repair.

A repair candidate must finish normally, fit 128 KiB, 64 nesting levels and 32,768 lexical tokens, and require at most eight punctuation edits. Only missing commas or closing delimiters and trailing commas may change. All original data tokens and non-comma delimiters remain in order. Closing an unfinished response at EOF, creating empty missing containers, inventing values or quotes, selecting partial rows, duplicate keys and competing objects are rejected. Reported truncation is never repaired.

Scene responses require one complete current object. There is no partial-core salvage, embedded Scene selection, speech-capture recovery call or retired-format parser. The current source, speaker, citation, witness, access, consent, revision and effect validators still decide whether repaired syntax can apply. Optional defaults apply only to complete current responses and never replace malformed supplied effects.

## Response ownership

The original completion remains unchanged in its provider checkpoint. Repairs cannot change request fingerprints, model settings, budgets, retry authorization or timeout policy. Complete accepted responses retain their ordinary local replay and exactly-once settlement guards. A late callback cannot apply effects or replace a selected response under a newer owner.

Jobs and operations bind Village seed, subject, source revision, attempt and admitted contract. Current background jobs persist a unique instance UUID before dispatch. Retry retains that instance and advances its attempt; replacement allocates a new instance. Delayed saves, source publication and public Retry actions check the exact identity. Reset, removed residents, changed inputs, supersession and teardown fence late effects.

Unknown provider outcomes remain uncertain. Reads, polling, notices, diagnostic writes and storage retries authorize no paid dispatch. Reuse a saved purchased result before considering an explicitly authorized replacement. A successful response alone does not establish a committed effect. Engine's buffered document writes do not provide a package-visible durable flush barrier, so a hard crash can still lose recently acknowledged evidence.

## Private diagnostics and validation

Ordinary diagnostics share a server-only log of 100 recent entries, each capped at 24,000 characters of redacted response text. Prompts and connection configuration are excluded. The opaque envelope owns no Gallery media and has no recovery authority. Eviction cannot release unfinished work or accounting uncertainty. Diagnostic publication is best effort and cannot change the original failure.

Current Scene, Founding, Routine, Wish, schedule, starting-history and selected-domain parsers retain their own completeness and source checks after bounded syntax recovery. Provider-free tests cover successful punctuation repair, ambiguous refusals, duplicate keys, truncation, bounded diagnostics, explicit replacement and saved-response replay. They do not establish a provider's conformance rate.
