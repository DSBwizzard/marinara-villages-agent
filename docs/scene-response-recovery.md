# Scene response recovery

Scene turns request JSON-object responses. The current Engine interface forwards the requested format without advertising strict-schema enforcement for an arbitrary selected endpoint. Villages does not change connection settings or purchase fallback requests.

The extractor requires one complete current object and a normal finish, optionally enclosed in a Markdown fence. Bounded value-preserving punctuation recovery runs before schema, source, witness and effect validation. Duplicate keys, ambiguous quotation boundaries, missing required fields and truncation are rejected. Complete narration cannot be salvaged from an incomplete response. See [model JSON recovery](model-json-recovery.md).

## Saved responses and diagnostics

Provider responses checkpoint before validation. Parser rejection preserves the submitted input and requires explicit replacement; local storage replay reuses saved output. The generation lifecycle's one bounded outcome correction is separate from parser repair. A late callback retains evidence without authorizing publication under another request owner.

Ordinary diagnostics share one server-only log of 100 recent entries, each capped at 24,000 characters of redacted response text. Prompts and connection configuration are excluded. The opaque diagnostic envelope owns no Gallery media and has no recovery authority. Eviction cannot release unfinished work, purchased responses or unknown accounting. Publication is best effort and cannot change the original failure. Redaction does not guarantee that story text contains no private information.

Noncritical optional effects can retain independent failures alongside accepted prose. Malformed consequential standing permissions or Project proposals fail the combined response before publication. Explicit selected-domain interpretation uses the original accepted evidence without rewriting prose. Reads, reloads and copying diagnostics purchase no inference.

## Lost turn connections

A failed browser connection can outlive the request while the server finishes a turn. The client retains the submission identity and reconciles saved receipts using reads only. It checks while visible for up to one minute, then offers Check saved reply; returning or reconnecting also checks. Missing operations do not prove success. Matching saved receipts establish completion, and matching failed operations establish failure.

A visible playback page is not the submission ledger. The latest saved submission provides committed/publication proof even when its reply falls outside the current page or a later close replaced the operation. Unpublished consequential effects remain held. Clarifications must match both submitted text and submission identity; reconciliation never sends a duplicate turn.

Late replies preserve newer composer edits, including edits with identical text, and retain the reading position. Pending reconciliation allows draft editing while preventing another submission until the outcome is known. Confirmed failure preserves the draft and explicit recovery controls.

## Hearing evidence and citations

Current nonverbal sounds use metadata on an ordinary narration segment. Full narration stays local; remote listeners receive only the permitted audible cue through soundOnly under the same line ID. Raised voices likewise distinguish heard words from indistinct sound. Routing creates no extra evidence line and grants no unseen visuals, attendance, access or movement.

Player speech binds exact submitted spans and one-based occurrences. When code inserts those source lines, numeric generated-segment indexes and utterance:N references are remapped; ordinary strings remain possible exact evidence IDs. Decimal-string indexes are not guessed. Every affected knower still needs the actual source and witnesses.

Ordinary responses omit private provider evidence, checkpoints and interpretation history. Copy details explicitly reads owner diagnostics for the displayed attempt or update result. That endpoint retains bounded failure/source context, protects credentials and marks unavailable or shortened details. Copying never replays work or changes Village time.

## Response timings and validation

Replies remain checked before display. Private diagnostics retain bounded server timings, checkpoint reuse and provider metrics. Nested spans must not be added as if independent elapsed times. The browser keeps at most twenty send-origin timing records containing IDs and durations; they clear with the tab. History reads do not create send timings.

Provider-free tests cover complete JSON handling, bounded diagnostics, exact sources, private hearing, explicit replacement, lost acknowledgements and saved-response replay. Those checks do not establish provider conformance, semantic quality, latency improvements or cost savings.
