# System ownership contracts

Target: 0.7.3. New Scenes use semantic contract 2. Existing Scenes and already admitted jobs retain their captured contracts; reading a save does not upgrade it or buy inference.

## Calls and authority

An ordinary Say / Do turn uses configured **System intent → Narration draft → System exchange**. An opening uses Narration → System exchange. Typed Move and Conclude remain deterministic. Narration supplies speech, visible prose, delivery and staging. Its memory, access, movement, physical, relationship, Wish and Project nominations are discarded before effect normalization. System independently discovers those effects from the complete current draft and scoped context. The old room/Project Decisions checks and selective consequential-proposal verifier are not stacked onto the new path. A complete simple conversational Wish verdict is consumed directly; compound, historical and receipt-dependent goals retain their specialist.

`features/generation/semantic-service.ts` owns System calls. `features/scenes/writing-service.ts` owns provisional prose and binds the independent exchange result. `features/scenes/command-service.ts` owns immediate application. Semantic provenance, hashes, operation IDs and authority flags are minted or checked by code. Model claims of verification or receipts confer no authority.

Code checks exact source spans/IDs, legal routes, witnesses, schema, capacity, stock/source claims, revisions and durable receipts. Ordered movement and speech use up to eight prepared Zone transitions; exact speech spans cannot cross a movement boundary. Physical receipts use the actual Zone and witnesses at the cited narration segment. Code does not use English verbs, relationship adjectives, name mentions or numerical affection thresholds to decide new-contract subjective meaning. Explicit mechanics, such as visitor hours, declared relationship access rules and construction deadlines, remain code rules.

## Failure, retry and recovery

Each principal System stage freezes context, source identity, configured connection/model and allowance in the existing operation journal. Completed responses and applied domain receipts replay locally. There is no automatic empty-response retry, semantic repair loop, model fallback or Narration replacement. Explicit retry replaces the selected failed System stage; a storage failure first replays the already saved result. Source hashes and saved memory versions prevent a changed source from silently acquiring an old interpretation.

The provisional turn is hidden until immediate physical, access, Project commitment and standing-permission authority has settled. Non-authority domain failures can leave completed dialogue visible, but block the next model turn, typed movement and Conclude/reopen. The user can Retry or explicitly Continue that failed domain. Continue is unavailable for pending or immediate-authority work. A saved world fence plus per-store receipts prevents late domain writers from applying after Continue. Repeated Continue and recovery after a partial save are idempotent. Natural conclusions wait for the same barrier and finish locally after recovery/Continue. The draft stays editable on desktop and phone.

Accepted offscreen encounters persist exact private evidence. Relationship and memory application replay independently; a failed memory status retains the outbox. No player notice or disclosed offscreen knowledge is manufactured. Starting ties and schedule preparation are finite jobs with source/lifecycle fences, not paid work on profile reads.

## Context, capacity and token boundaries

The current shard plan is one packet per principal System stage, each at most 12,000 fitted input tokens and 2,400 output tokens (or the model's lower supported allowance). Required evidence must fit unchanged. An oversized packet fails before dispatch. Two ordinary principal calls therefore reserve up to 24,000 input / 4,800 output tokens, plus the existing Narration allowance. A new v2 Scene attempt also freezes a whole-operation ceiling of 12 requests, 144,000 estimated input tokens and 32,768 requested output tokens, including any Scene-coordinated specialist/relay work. Reservations are journaled before dispatch; replayed results consume no new allowance. Explicit retry gets a new attempt reservation while retaining successful results. Lifecycle/background jobs retain their separate finite admission and per-request limits. These are conservative ceilings, not observed usage or cost estimates; provider prefix caching and real-model latency/quality are unmeasured.

Retrieval includes bounded selected memories and up to 64 authorized source/version catalog hints. Hints locate sources; they cannot prove an outcome or absence. System may request up to eight exact catalog IDs. Code saves full, still-authorized version-matched sources and stops. Only an explicitly admitted retry performs inference with the expanded packet, under the same limits. One expansion is available per stage; another request or uncovered necessary scope stays unresolved. This is not unlimited history search or a semantic index.

The physical storage contract supports one persistent state patch per exchange, bound to its exact narration segment. Ordered player Zone movement mixed with speech is supported; multiple persistent physical steps needing intermediate receipts remain unresolved. Legacy visit invitations that require consumption still use the existing typed Move transaction before mixed speech. These are explicit supported-effect capacity boundaries, not keyword-based opinions about reasonable actions.

## Provider-free validation

`tests/villages-semantic-ownership.regression.ts` covers configured System routing, the actual three-stage writer, saved/frozen replay, token-fit rejection without dispatch, context expansion with an explicit retry, access scopes/conditions, provenance scrubbing, legacy decoding and authority/Continue boundaries. `villages-semantic-lifecycle.regression.ts` covers saved-result application failures, edited ties, routine source fences, finite influence preparation, private offscreen memory recovery, duplicate units and late-writer fences.

`villages-zone-events-packaged.regression.ts` runs archive-identical server bytes through actual HTTP handlers with synthetic models/storage. `villages-scene-send-recovery.e2e.mjs` tests drafts, explicit retries and Continue on desktop/phone. Related memory, Wish, Project, relationship, founding, access and coordinator suites remain applicable. Mocked HTTP/browser evidence does not establish actual Engine compatibility, real-provider quality or measured token savings. Those acceptance/publication gates remain separate.
