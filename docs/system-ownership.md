# System ownership contracts

New Villages require social contract 2 before normalization or startup recovery. Unsupported older worlds remain untouched. New Scenes use semantic contract 2 and combined pipeline 3; saved jobs retain their captured inputs and reading never buys inference.

Opening pitch meaning belongs to System. New combined pitch results carry a server-created fingerprint of the frozen prepared proposal. Application checks that identity against the current proposal and retains exact witnessed speech, Scene eligibility and once-only reveal guards; it does not require the entire authored title inside one quote. The fingerprint stays private. Older saved results retain their original title check.

## Calls and authority

An ordinary Say / Do turn and an opening use configured **Narration draft → combined System interpretation**. System interprets the original input and draft together; a separate intent request is not added to the new path. Typed Move and Conclude remain deterministic. Narration supplies speech, visible prose, delivery and staging. Its memory, access, movement, physical, relationship, Wish and Project nominations are discarded before effect normalization. System independently discovers those effects from the complete current draft and scoped context. The old room/Project Decisions checks and selective consequential-proposal verifier are not stacked onto the new path. A complete simple conversational Wish verdict is consumed directly; compound, historical and receipt-dependent goals retain their specialist.

New Wish checks can restore exact actor-witnessed excerpts from up to four earlier applied Wish receipts, retaining at most sixteen historical excerpts. The server verifies the current Wish identity, source Scene/turn, witness and time; rejected receipts supply no proof. This does not disclose an unrevealed Wish or add a model stage. Already admitted jobs reuse their frozen inputs without reading archives again.

`features/generation/semantic-service.ts` owns System calls. `features/scenes/writing-service.ts` owns provisional prose and binds the independent exchange result. `features/scenes/command-service.ts` owns immediate application. Semantic provenance, hashes, operation IDs and authority flags are minted or checked by code. Model claims of verification or receipts confer no authority.

Code checks exact source spans/IDs, legal routes, witnesses, schema, capacity, stock/source claims, revisions and durable receipts. Ordered movement and speech use up to eight prepared Zone transitions; exact speech spans cannot cross a movement boundary. Physical receipts use the actual Zone and witnesses at the cited narration segment. Code does not use English verbs, relationship adjectives, name mentions or numerical affection thresholds to decide new-contract subjective meaning. Explicit mechanics, such as visitor hours, explicit Venue access policies and construction deadlines, remain code rules.

## Failure, retry and recovery

Each principal System stage freezes context, source identity, configured connection/model and allowance in the existing operation journal. Completed responses and applied domain receipts replay locally. There is no automatic empty-response retry, semantic repair loop, model fallback or Narration replacement. Explicit retry replaces the selected failed System stage; a storage failure first replays the already saved result. Source hashes and saved memory versions prevent a changed source from silently acquiring an old interpretation.

The provisional turn is hidden until immediate physical, access, Project commitment and standing-permission authority has settled. Non-authority domain failures can leave completed dialogue visible, but block the next model turn, typed movement and Conclude/reopen. The user can Retry or explicitly Continue that failed domain. Continue is unavailable for pending or immediate-authority work. A saved world fence plus per-store receipts prevents late domain writers from applying after Continue. Repeated Continue and recovery after a partial save are idempotent. Natural conclusions wait for the same barrier and finish locally after recovery/Continue. The draft stays editable on desktop and phone.

Accepted offscreen encounters persist exact private evidence. Relationship and memory application replay independently; a failed memory status retains the outbox. No player notice or disclosed offscreen knowledge is manufactured. Starting ties and schedule preparation are finite jobs with source/lifecycle fences, not paid work on profile reads.

## Context, capacity and token boundaries

Each principal System stage sends one packet whose required evidence must fit the configured model unchanged, with a 4,096 output ceiling for the combined interpretation (or the connection's lower supported allowance). Context fitting cannot discard required evidence. An ordinary turn uses one such System reservation plus the existing Narration allowance. A new v2 Scene attempt freezes a whole-operation ceiling of 12 requests, 144,000 estimated input tokens and 32,768 requested output tokens, including any Scene-coordinated specialist/relay work. Reservations are journaled before dispatch; replayed results consume no new allowance. Explicit retry gets a new attempt reservation while retaining successful results. Lifecycle/background jobs retain their separate finite admission and output limits and use the same unchanged-evidence model context check. These are conservative ceilings, not observed usage or cost estimates; provider prefix caching and real-model latency/quality are unmeasured.

Narration searches the full frozen eligible Memories collection before generation. The existing combined System stage performs a fresh local search using input and the saved Narration reply; it receives at most 1,800 estimated tokens including source excerpts, metadata and administrative protection. Every proposed write supplies clear/conflict/uncertain screening against that context. Malformed, changed or insufficient screening rejects affected proposals individually while dialogue and independent effects survive. Oversized relevant protection marks the context incomplete without blocking unrelated proposals. No expansion or additional verification call is purchased.

The physical storage contract supports one persistent state patch per exchange, bound to its exact narration segment. Ordered player Zone movement mixed with speech is supported; multiple persistent physical steps needing intermediate receipts remain unresolved. Legacy visit invitations that require consumption still use the existing typed Move transaction before mixed speech. These are explicit supported-effect capacity boundaries, not keyword-based opinions about reasonable actions.

`villages-zone-events-packaged.regression.ts` runs archive-identical server bytes through actual HTTP handlers with synthetic models/storage. `villages-scene-send-recovery.e2e.mjs` tests drafts, explicit retries and Continue on desktop/phone. Related memory, Wish, Project, relationship, founding, access and coordinator suites remain applicable. Mocked HTTP/browser evidence does not establish actual Engine compatibility, real-provider quality or measured token savings. Those acceptance/publication gates remain separate.

## Founding preparation

The Agenda is the resident's schedule; Routine is its recurring foundation. Wishes are desires that may influence scheduling. Their broader saved-data ownership remains a separate migration task.

Founding now uses independent, versioned Routine (the existing agenda job slot) and Initial Wish jobs. Routines run in roster order, followed by Initial Wishes, under existing connection concurrency limits. Timeout and response-validation failures do not stop other residents; definitive connection/auth/JSON-mode configuration failures stop the pass. Readiness requires a completion receipt for both tasks for every resident. A null Wish is a completed task; the initial daily-allowance reservation alone is not.

Each request carries one instruction block and structured identity, setting, circumstances, role, relevant places and lore. Complete authored identity is preserved; context fitting must fail rather than drop it. Routine requests reserve at most 2,048 output tokens; Initial Wish requests reserve at most 1,536, both respecting the connection cap. Both use JSON mode, no requested reasoning, the shared two-minute provider watchdog, and no automatic replacement request. The watchdog allows legitimate longer System work to finish while retaining cancellation, late-response evidence and explicit retry after timeout. Shared bounded JSON recovery precedes domain validation.

Routine application preserves Wishes; initial Wish application preserves the schedule. The founding-purpose exception allows exactly the owned seed/resident/task/allowance to apply while background pace is off, without enabling daily autonomy. Task receipts bind source revisions and contract version; stale or late results cannot apply. Public preparation snapshots contain statuses, attempts and receipts, never frozen prompts or raw replies.

The existing preparation retry route accepts a resident/task target, expected attempt and action ID. Batch retries skip completed work and include untouched pending tasks. Repeated action IDs reuse the same admission. Reads and startup never authorize new founding requests. Interrupted work waits for explicit retry; already saved results can apply locally.

An explicit retry migrates unfinished legacy combined jobs: matching applied successes are adopted, and valid Routine/Wish portions of saved responses are recovered independently. Unusable portions alone receive new jobs. Original requests, responses and unknown-billing evidence remain in private background history when replaced. Source changes forbid reuse. Private diagnostics record task/contract, input size, output allowance, elapsed request time, finish reason and validation outcomes; they do not estimate provider queue or inference timing.

Provider-free coverage includes founding-preparation, founding-requests, compact-founding, wish-lifecycle, founding-preparation browser and founding-jobs-packaged regressions. This establishes contracts and recovery behavior, not real-provider latency or output quality.

Connection admission and request outcomes are distinct, following Engine's separation of admission from generation. Authentication, missing connection/model/base URL, and rejected JSON-mode configuration pause shared background admission until an explicit successful retry. A timeout, transport failure or invalid response fails only its task; it never retries automatically or pauses unrelated tasks. Legacy shared pauses remain conservative admission guards. A deliberate founding retry admits its selected/unfinished tasks through that guard; an inherited pause flag is not evidence that a newly dispatched request failed configuration.

Private background checkpoints record package queue/admission time and total public-host call time, requested output allowance/reasoning, and completed versus unknown response outcome. The last eight explicitly retried attempts retain metadata without raw replies. Host duration includes Engine admission/backoff and upstream work; the public completion API exposes no first-token or provider-queue timing. Reasoning is a requested setting, subject to Engine connection overrides and upstream support, not an observed guarantee. Diagnostic writes and late failures obey the same attempt/owner/supersession fences as generation.
