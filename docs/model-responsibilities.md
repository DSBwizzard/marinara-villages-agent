# System and Narration responsibilities

New Scenes use the [System ownership contracts and register](system-ownership.md). Narration writes dialogue and observable events. One combined System interpretation normally follows, interpreting social meaning alongside memories, Wishes, Projects, access and physical authority. Code validates source identity, citations, witnesses, revisions and explicit permissions before committing effects or publishing consequential dialogue.

Relationships are qualitative resident-owned perspectives. System interprets history, boundaries, mutual terms and social intentions without inventing player feelings or consent. It retains separate captured-Scene and current-live after-values. A delayed source cannot erase a later ending or revive incompatible terms. Neither scores, keyword rules nor automatic decay substitute for interpretation.

Starting social history is finite System preparation from exact authored cards, player backstory and selected lore. It allows up to 8,192 output tokens or the configured model's lower ceiling; truncation requires explicit retry. Real contradictions ask for targeted creator clarification; later admissions and card refreshes preserve played developments. Personal mail uses Narration followed by System, with up to 2,048 and 16,384 output tokens respectively, respecting lower configured limits. System mail requests low reasoning. Exact outgoing text is durable before dispatch, original delivery settles before its reply, and unread disclosures remain outside the notebook. Reading and local storage replay call no model.

Automatic resident activity shares one daily review allowance: Off 0, Quiet 2, Average 6 and Busy 12. Live reviews are at least 60, 30 and 15 minutes apart respectively, including across midnight. Each review reserves before dispatch and permits at most two principal requests, including a second System interpretation when an encounter or message is written. Failed, empty and unknown attempts count. Absence catch-up shares this allowance and is capped at six opportunities without live spacing; new batches retain the Village-local return budget date and cannot purchase unstarted work on a later day. A retained failure prevents automatic replacement; explicit reinterpretation keeps the original source words.

Source receipts and delivered-mail receipts are immutable replay authority. Invalid or stale consequential meaning retains a visible recovery hold. Local replay makes no provider request. Explicit reinterpretation admits current settlement context and uses System; concurrent duplicate recovery requests reuse active work.

## Token and cost boundaries

Character cards, authored instructions and user writing preferences remain intact. Context fitting may remove optional history, recollections or lore, but must reject the request before spending if the complete required identity cannot fit. New Zone-event operations capture writing contract version 2 and a private capability manifest at admission. Retries retain that contract and eligibility; legacy saved operations keep their original schema. Unsupported versions or malformed manifests fail before provider work.

The version 2 contract omits unused effects, empty arrays and ordinary/main defaults. Only a complete, unambiguous JSON reply with a normal stop can receive these defaults; malformed supplied effects and truncated replies still fail. Code expands numeric speech sources into the exact complete original segment, preserving attribution, conditions, negation and index order. Oversized source-only disclosures or Project quotations are rejected; existing explicit summary/quote forms remain available. These references confer no authority and pass through the same witness, meaning and settlement checks.

Version 2 can discard validated movement metadata that merely restates a local resident’s current Zone. Every row still participates in actor, citation, conditional, destination and duplicate checks before filtering. Remote no-ops and narration naming another Zone remain rejected; real crossings retain their existing name, path and authority requirements. Discarded no-ops never enter witness routing, movement or settlement. The known spoken-aside delivery shorthand maps to ordinary delivery plus aside presentation only when it conflicts with neither presentation nor a whisper target; other unknown delivery values still fail.

Contract instructions are conditional on captured available capabilities and actual Wish/Project context, not inferred player intent. Spontaneous available proposals remain supported. Authored identities, complete instructions and player prose preferences stay required and unchanged. The existing prose foundation is retained: shortening it did not establish a quality improvement.

A single history block deduplicates eligible evidence and recent visible narration. It retains whole exact lines within a 12,000-character serialized-row budget, without cutting away conditions after a fixed character offset. Only retained eligible evidence IDs are citable; narrator continuity never grants residents knowledge. Very long lines can reduce the number retained, and optional history can still be dropped by context fitting. This is bounded recent continuity, not unlimited memory.

Resident activity and quiet Wish reflection share the existing bounded background allowance; time and schedule reconciliation are code operations. Provider output allowances, failed requests, selective checks and background generation all contribute to total play cost. A cheaper writer is useful only when its characterization, protocol adherence and decision proposals remain acceptable.

Native provider caching and streaming require verified Engine support. Prompt organization alone is not evidence of cache savings. Model prices and compatible providers vary, so cost comparisons should use matched cards, history, output targets and complete request chains.
