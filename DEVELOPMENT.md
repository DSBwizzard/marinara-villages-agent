# Villages development workspace

This folder is the active Villages development workspace. Work from the Villages files at the repository root. It is a Villages-only development copy, not a complete checkout of the official Marinara-Agents monorepo.

## Build

Requires Node.js 24 or newer and an installed Marinara Engine checkout with its dependencies. In PowerShell:

```powershell
npm ci
$env:MARINARA_ENGINE_ROOT = Read-Host 'Path to the installed Marinara Engine checkout'
node scripts/build-feature-packages.mjs villages
```

Change `MARINARA_ENGINE_ROOT` if your Engine checkout is elsewhere. Before packaging a code change, increment Villages `version` in the `villages` entry of `scripts/build-feature-packages.mjs`. The build uses the Engine source snapshot under `sources/engine`, overlays Villages source, and writes generated files under `packages/villages/`, a zip under `artifacts/`, and a Villages-only local catalog under `catalog/`. The local catalog is ignored by Git because its URLs target the official multi-agent repository.

## Install into the existing Engine

Sprite Studio runs within Marinara Engine and uses its character sprite library, image connections, saved style profiles, configured defaults and fallbacks, sprite-sheet generation, inspection, cleanup, and sprite storage. The public shared profile normalizer and prompt compiler enter the Villages build through `sources/package-shared.ts`. Villages previews provider dimensions, submits its opaque-matte prompt override through the sprite-sheet API with generation cleanup and native transparency disabled, saves the untouched original, then cleans Engine-returned crops separately and fits transparent Scene cutouts. No Engine source edits or builds, separate connections, design approvals, or AI review passes are required. Sideloading a merged, validated Villages package through the helper below is allowed.

The sideload helper installs Villages into either an existing package registry or a fresh data directory. It preserves other installed package records and saves a registry backup when one already exists. After the package has merged to `staging` and passed checks and build, run:

```powershell
$version = (Get-Content packages/villages/manifest.json -Raw | ConvertFrom-Json).version
$archive = ".\artifacts\villages-$version.zip"
node scripts/sideload-villages.mjs $env:MARINARA_ENGINE_ROOT $archive villages
```

The helper copies the generated `packages/villages/` output into the Engine's versioned capability-package directory and updates its installed-package registry. Restart Marinara Engine afterward so it loads the updated server package.

The local catalog generated by this Villages-only copy uses artifact and documentation URLs under `Pasta-Devs/Marinara-Agents`. Use the sideload command above for this local workspace; do not publish its single-package catalog as a replacement for the official multi-agent catalog.

## Checks

```powershell
npm run check
```

Sprite reliability checks:

```powershell
npx tsx tests/villages-sprite-engine.regression.ts
npx tsx tests/villages-sprite-pixels.regression.ts
npx tsx tests/villages-sprite-studio.regression.ts
npx tsx tests/villages-sprite-library.regression.ts
npx tsx tests/villages-sprite-pipeline.regression.ts
npx tsx tests/villages-resident-sprites.regression.ts
node tests/villages-sprite-studio.e2e.mjs
```

To validate the six recorded Roxie sources locally, set `ROXIE_SPRITE_DATA` to the installed Engine's sprite data directory before running the pixel regression. This reads images without modifying the installation or committing personal artwork. The normal workflow makes no AI review calls; these checks exercise deterministic processing and recovery without paid image generation.

Focused Villages tests are under `tests/`. Package source and generated outputs are under `packages/villages/`.

## Git scope

This is a selected subset for a Villages-only working repository. It is not suitable for replacing the official Marinara-Agents repository, which tracks all agent packages and their shared catalogs. If you later want to contribute Villages into that official monorepo, use a full checkout and transfer only the Villages changes into it. You handle all Git operations for this folder.
